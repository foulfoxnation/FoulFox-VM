10 suggestions for the Ryzen 5600 / 16–32GB / 1TB / GTX 1070 Ti build
That machine changes the game: 6 cores/12 threads with proper KVM, room for Windows + local AI at once, and a real GPU. Suggestions ordered by impact:

GPU passthrough for the Windows VM. Hand the 1070 Ti directly to the guest (VFIO). Windows gets real graphics — smooth desktop, GPU-accelerated apps — instead of software-emulated video. Biggest single upgrade for "agent using a real PC." Trade-off to plan around: while the VM owns the GPU, the host kiosk needs to run on the CPU's... wait, the 5600 has no integrated graphics — so this means either a second cheap display card for FoulFox OS, or a "headless host" mode (next item).
Headless host mode. Let FoulFox OS boot without its own screen and serve the whole shell over the network (the Session Portal already exists) — then the 1070 Ti can go 100% to the VM and you drive everything from your laptop. This sidesteps the no-iGPU problem entirely.
GPU-accelerated local AI when the VM is off. The 1070 Ti (8GB VRAM) runs 7–8B models fast on Ollama with CUDA. Add NVIDIA/CUDA support to the ISO and an automatic "GPU is free → AI uses it; VM starts → AI falls back to CPU" arbiter. Same card, two jobs, never fighting.
Right-size the VM automatically to this class of machine. With 32GB: give Windows 12–16GB and 4–8 vCPUs instead of today's conservative defaults; with 16GB, cap at 8GB and park the local model while the VM runs. Detect at provision time, not hardcoded.
Fast dedicated VM storage layout. On the 1TB SSD, pre-plan partitions at install: OS (~40GB), VM disks (~600GB), AI models (~100GB), workspace/scratch. Grow the Windows disk to 256GB on big-disk machines so the agent can install real toolchains (Visual Studio alone wants 40GB+).
Snapshot-per-coding-session becomes practical. With this much disk and CPU, take an automatic qcow2 snapshot before every agent coding session and keep the last N — one-click "undo everything the agent did today."
Parallel agent workers. 12 threads means the agent suite (worker/architect/reviewer) can genuinely run concurrently, and sub-agents can compile/test in the VM while the main agent keeps planning. Raise the scheduler's concurrency when core count allows it.
Dev-tools golden image. After first Windows install, have the agent unattended-install a coding baseline (Git, Python, Node, VS Code) and snapshot that as the "vibe-coding ready" base image — every new VM clones from it in minutes instead of reinstalling Windows.
Thermal/health telemetry in the shell. A real GPU + sustained AI/VM load means heat. Surface CPU/GPU temps, fan, RAM pressure, and disk wear in the Diagnostics tab with alerts, so a long agent session can't silently cook or swap-thrash the box.
A benchmark drill on first boot of new hardware. Extend the "vibe check" idea: measure tokens/sec on the local model, VM boot time, and disk speed, store it per-machine, and show "this machine scores X — expect smooth/slow agent coding." Turns your next build (and any future one) into a known quantity immediately.
If you want my order of operations once the parts arrive: 2 → 4 → 3 → 8 — that gets you a headless, right-sized, GPU-accelerated vibe-coding box without touching the trickier passthrough work first.
