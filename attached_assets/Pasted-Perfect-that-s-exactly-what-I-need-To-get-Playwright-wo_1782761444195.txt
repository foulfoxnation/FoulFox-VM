Here's why each one matters for the approach:

OS / arch — confirms which Playwright build and browser channel to target.
Node in the VM — tells me whether Playwright can run inside the VM (launching the browser locally), or whether it has to drive the VM's browser remotely from the Peekaboo process.
Installed browsers — if Chrome/Edge is already there, Playwright can use it via channel: "chrome"/"msedge" instead of downloading its own ~300 MB Chromium.
Port 9222 — the cleanest path is chromium.connectOverCDP() to a browser launched with --remote-debugging-port. If that port is reachable, Playwright gets full programmatic control while still running in the VM's stealthy desktop environment.
Internet egress — determines whether we can playwright install browsers or must reuse an installed one.
