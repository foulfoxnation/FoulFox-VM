2. Your install instructions — what "admin level, no prompts" actually requires
Important framing: the voice app itself should not run as admin. The correct architecture is: the app listens and talks freely, and asks the OS broker to do privileged things. Running the HTTP server itself as admin would hand root to anything that can reach port $PORT.

On the FoulFox machine, at install time (admin console):

Install prerequisites system-wide (this is the actual admin part):
Python 3.11 + FFmpeg on PATH
Ollama installed as a system service so it's up before login: ollama pull llama3.1:8b
Optional CUDA drivers for GPU acceleration
Install the app via FoulFox's normal flow (paste repo URL / zip). Do not bypass the installer — the data dir keying and update path depend on it.
Grant persistent permissions (admin settings for this app id foulfox-voice):
Microphone: Always allow, delegated into the app iframe, persisted across reboots
Audio autoplay: allowed without gesture
Background execution: exempt from tab/iframe throttling
Enable autostart so the voice agent is live at login with no interaction.
If the AI should control the OS by voice: enable capability agent.task for this app in FoulFox's capability manager. All privileged actions then flow through FoulFox's broker with its own audit/consent policy — that's where "admin level" lives, not in our process.
First run only: leave networking on so model weights download into $FOULFOX_APP_DATA_DIR/models/; after /healthz goes 200 it runs fully offline.
What "communication without prompts" then looks like: app autostarts → mic is already granted → continuous VAD listens → speech is transcribed locally → Ollama replies in persona → cloned voice speaks the answer → you can interrupt mid-sentence. No buttons, no wake prompts.
